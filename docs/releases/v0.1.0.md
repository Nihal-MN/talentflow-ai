## Overview

TalentFlow AI is an open-source, AI-native hiring pipeline: it turns job
descriptions and resumes (PDF/DOCX/TXT) into **validated structured data**,
matches candidates **requirement-by-requirement** with **quoted evidence from
their own resume** and a **published scoring formula**, and carries them
through a real hiring pipeline with notes, tags and grounded screening
questions. It runs fully **without an API key** (deterministic mock AI, labeled
everywhere) and uses the **OpenAI API with structured outputs** when a key is
configured.

The design position: recruiting automation should assist a human who stays
accountable. No opaque scores, no protected characteristics, no pretending the
demo is a model.

## Highlights

- **Explainable matching** — every requirement gets `met` / `partial` /
  `missing` / `unknown` with a written reason and evidence that either *quotes
  the resume verbatim* or is explicitly labeled computed. The composite score
  renders its own formula next to it.
- **Structured ingestion** — LLM structured outputs (or the deterministic
  mock) validated by Pydantic schemas, then normalized; nothing unvalidated
  reaches the database. Every record carries its AI provenance
  (`extraction_method`: `mock` / `openai`).
- **Semantic search** — pgvector on PostgreSQL (HNSW cosine index) with an
  in-process fallback on SQLite; similarity is a supporting signal that can
  never override a deterministic miss.
- **Recruiter workflows** — pipeline stages with an append-only audit trail,
  notes, tags, and screening questions generated from match results, each
  with a rationale.
- **Zero-config demo** — `docker compose up --build` + seed; 4 synthetic jobs
  and 10 synthetic candidates ingested through the real pipeline.
- **Quality** — 95 backend tests (91% coverage; PostgreSQL+pgvector
  integration included) + 18 frontend tests; ruff / ESLint / strict tsc; CI
  on GitHub Actions; CodeQL; Dependabot.

## Quick start

```bash
git clone https://github.com/Nihal-MN/talentflow-ai && cd talentflow-ai
cp .env.example .env
docker compose up --build -d
docker compose exec api python -m app.seed
# UI: http://localhost:3000 · API docs: http://localhost:8000/docs
# Health: http://localhost:8000/api/v1/health
```

Optional live mode: set `OPENAI_API_KEY` in `.env` and restart the `api`
service — extraction then runs on the OpenAI API and records are labeled
`openai`.

## Current capabilities

Jobs (paste/upload → structured requirements) · candidates (multi-file
resume ingestion → validated profiles with evidence-carrying skills) ·
requirement-level explainable matching with ranking · pipeline board with
audit trail · notes & tags · screening-question generation · system health
report · provider architecture (OpenAI + deterministic mock) · PostgreSQL +
pgvector or SQLite · Docker Compose stack.

## Known limitations

- **No authentication** — do not expose the demo to the public internet as-is.
- The mock extractor is a curated, English-centric lexicon: precision over
  recall. It powers the keyless demo and is always labeled.
- **The OpenAI path is wired and contract-tested but was not exercised
  against the live API in the release environment** (no key available). Mock
  mode is what the demo shows.
- Years of experience are computed from resume dates; scanned/image PDFs are
  rejected (no OCR); single-process deployment profile (demo scale).

## Responsible AI requirement

TalentFlow is **decision-support software**. It must not make hiring
decisions, and it must not rank candidates using protected characteristics —
no column, prompt or code path exists for age, gender, ethnicity, religion,
disability, marital status, sexual orientation or photos; a structural test
fails the build if one ever appears. The recruiter decides, always. See
[RESPONSIBLE_AI.md](../../RESPONSIBLE_AI.md) — it is a contract, not
marketing.
